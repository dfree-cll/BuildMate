# BuildMate 全项目优化基线

更新日期：2026-09-07

本文记录本轮“全项目优化”已经落地的改动、仍存在的技术债和后续拆分顺序。优化遵循
正确性、稳定性、可维护性优先，不以删除测试或隐藏失败换取表面绿灯。

## 本轮已完成

### BIM 与 Revit

- L/T/X 节点按相交墙单侧半厚度修剪，避免核心筒墙体断缝。
- 墙体碰撞审计增加工程级浮点误差下限，仍保留真实碰撞告警。
- Revit 编译器使用当前确定性墙体合同。
- 交付平面和三维视图显式打开墙、结构柱、结构梁、轴网类别。
- 墙体写入时同步设置 Revit 原生结构墙标志和 `BM_WallRole`。
- 多文件上传由串行改为最多 3 路有界并发，避免 50 张图纸线性等待或无限并发。
- Artifact Store 使用活动上传计数，多个文件并发时不会过早清除 loading 状态。

### 安全与数据隔离

- 退役 旧 BIM JSON 接口在生产环境拒绝任意服务器路径，只允许 BuildMate 数据目录中的来源文件。
- RAG 检索审计在缺少 `project_id` 时只返回租户级记录，不再跨项目读取历史检索。
- 保留本地离线演示的路径兼容；新业务仍必须使用当前 Artifact/Workflow 合同。

### 工程卫生

- 运行时缓存统一位于可随时再生的忽略目录，不属于业务源代码。
- 增加核心筒 T 节点回归测试，防止后续几何重构重新引入双向修剪断缝。
- 同步更新 `WALL_PIPELINE.md` 与 `CURRENT_STATUS.md`。

## 当前真实基线

## 当前维护原则

- 所有新功能统一进入持久化任务运行时、当前 API 合同和 `wall_pipeline` 主链。
- 外部调用必须具备超时、有限重试、结构化错误和可观察日志。
- 业务数据始终按租户、项目和操作者隔离；审批、模型和事件以数据库为事实源。
- 任何 Revit 写入都必须通过静态校验、Dry-run、人工审批和独立叠图验收。
- 删除或替换模块前，先完成调用方迁移、回归测试和现场冒烟验证。
