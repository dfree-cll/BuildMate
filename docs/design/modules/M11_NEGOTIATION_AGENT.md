# M11 采购与供应商 Workflow 设计

## 功能描述

作为问答入口或审核端可调用的后台 Workflow，帮助项目人员基于供应商资料、合同条款和项目要求完成采购判断、谈判准备、风险识别和交底纪要。用户不需要单独选择“谈判 Agent”。

## 功能实现流程

1. 通过 `procurement_query` 意图或审核端创建任务，绑定项目、供应商和资料。
2. 通过 RAG 检索合同、制度、资质、历史资料和项目要求；通过结构化接口读取价格、预算、交付和供应商主数据。
3. 采购查询可即时返回事实和依据；谈判/正式纪要按准备 → 议题 → 风险 → 纪要阶段推进。
4. 每轮输出事实依据、建议话术、风险和下一步动作。
5. 纪要进入人工确认；确认后生成只读版本。

## 业务规则

- Agent 每轮只能推进一个有限阶段。
- 合同事实必须引用原文和版本。
- RAG 文档证据与结构化价格/预算/供应商事实必须分开标记，不能互相替代。
- 未确认纪要不是正式合同或承诺。
- 不得自动改变价格、交付承诺或合同条款。
- 会话按项目和供应商权限隔离。

## 使用角色

项目工程师发起；审核员/管理员可审核纪要；采购/授权用户参与会话；普通用户按权限只读。

## 界面设计要求

- 左侧显示阶段、议题和风险；中间为对话；右侧为证据和供应商资料。
- 未确认纪要使用醒目“草稿”标签。
- 每轮展示下一步动作和依据，可复制但不能静默发布。

## API 与数据

- `POST /api/v2/chat/sessions`、消息和阶段事件 API；正式采购/纪要使用 `/api/v2/workflows`。
- 会话、消息、RetrievalRun、KnowledgeFeedback、Approval 和 AuditEvent。

## 异常与验收

- 资料缺失、RAG 无命中和模型超时显示为不确定，不编造供应商事实。
- 每轮状态持久化；正式纪要必须有审批事件。
