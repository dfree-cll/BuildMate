# M10 合同审核 Workflow 设计

## 功能描述

作为问答入口可调用的后台 Workflow，对合同及其附件进行条款级审查，结合规则、项目制度和规范输出可追溯的风险判断。用户不需要单独选择“合同 Agent”。原采购审批实现作为迁移期兼容能力保留，迁移完成后归入 M11。

## 功能实现流程

1. 用户在问答中提出“审核这份合同”，或从审核端选择合同 Artifact。
2. 系统校验合同版本、项目范围和附件完整性。
3. 规则引擎检查期限、金额、付款、违约、责任、范围和版本等事实。
4. RAG 检索制度、规范、项目模板和相关条款，同时读取合同结构化事实；LLM 只生成风险摘要、解释和建议。
5. 每条 Finding 同时绑定 RAG 原文页码/段落、结构化字段来源和规则版本；高风险或证据不足进入审核员/管理员审批。
6. 记录批准、驳回、退回补件和最终决定。

## 业务规则

- 金额、日期、主体、范围和版本是事实字段，LLM 不能修改。
- 合同原文、项目制度和规范版本不可被覆盖；冲突时必须提示。
- 证据不足、条款缺失或版本冲突默认进入待补/人工审核。
- 审批人不能审批自己提交的高风险审核（按租户策略配置）。
- 所有决定必须有理由和证据。

## 使用角色

`project` 发起；`reviewer/admin` 审批；`user` 查看被授权结果；问答意图路由负责创建任务。

## 界面设计要求

- 顶部显示合同版本、项目、审核范围和任务状态。
- 结果按条款/风险分组，显示严重级别、原文定位、规则、证据和建议。
- 审批按钮显示将产生的业务影响并要求原因；聊天消息不能替代审批。

## API 与数据

- 问答意图：`contract_review`；任务工作流：`workflow=contract_review`。
- `POST /api/v2/workflows`；审批复用 `/tasks/{id}/resume`。
- `ReviewFinding`、`Approval`、`Knowledge*`、`TaskEvent` 和 `ToolCall`。

## 异常与验收

- 价格服务超时、资质缺失、重复申请和预算冲突明确失败/待补件。
- 重复提交不创建重复申请；审批可审计和回放。
