# M03 文件与 Artifact 设计

## 功能描述

统一管理原始文件、中间 JSON、渲染图、RVT、差异报告和审计报告。Artifact 是不可变来源和交付物的身份，不把本地路径当作事实源。

## 功能实现流程

1. 前端选择项目和文件，显示扩展名/大小校验。
2. API 检查文件头、媒体类型、大小、空文件和路径安全。
3. 计算 SHA-256，写入本地目录或对象存储。
4. 创建 Artifact 元数据和权限范围。
5. Worker 为转换、渲染、JSON、RVT 和报告登记派生 Artifact。
6. 下载时再次校验租户、项目、角色和资源状态，返回短时地址或受控流。

## 业务规则

- 文件内容不可修改；更新必须创建新 Artifact 和父子谱系。
- 允许的 BIM 来源为 PDF/DWG/DXF；IFC/图片不进入 BIM Agent 墙体主链路。
- 同一内容按内容哈希幂等，不能重复产生事实版本。
- 数据库保存 URI、哈希和元数据，大文件不塞入业务表。
- 客户端路径仅作显示信息，不用于服务器读取。

## 使用角色

- `admin`：查看租户 Artifact、归档和治理。
- `project`：上传项目文件和下载结果。
- `reviewer`：读取审批所需证据和产物。
- `user`：下载被授权的只读结果。

## 界面设计要求

- 上传区显示格式、大小、进度、哈希校验和失败原因。
- 文件列表显示文件名、类型、版本、状态、来源角色、创建者和时间。
- 派生物以“来源 → 产物”展开显示，禁止只显示一个无解释的下载链接。
- 失败文件允许重试或重新选择，不自动覆盖原文件。

## API 与数据

- `POST /api/v2/artifacts`、`GET /artifacts/{id}`、`GET /artifacts/{id}/download`。
- 表：`artifacts`、`artifact_derivatives`。
- 存储适配器：本地文件、MinIO/S3。

## 异常与验收

- 空文件、实体超限、扩展名伪造、存储失败和哈希不一致均显式失败。
- 跨项目下载拒绝；服务重启后 Artifact 仍可查询。
- 任一结果可沿谱系找到源文件、配置和处理版本。
