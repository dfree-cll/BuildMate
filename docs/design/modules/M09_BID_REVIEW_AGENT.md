# M09 标书查询与审查 Workflow 设计

## 功能描述

作为问答入口可调用的后台 Workflow，对当前项目投标文件进行检索、定位、摘要、版本对比和正式审查，输出有页码证据的结果。用户不需要单独选择“投标 Agent”。

## 功能实现流程

1. 从问答意图 `bid_query` 或审核端创建请求，上传/选择投标资料并归属项目。
2. 普通查询直接执行定位和摘要；用户要求正式审查报告时，创建任务并选择模板和风险阈值。
3. 解析文档、建立项目隔离索引。
4. 并行执行商务、技术、风险和响应完整性检查。
5. 需要规范/合同依据时调用 RAG。
6. 合并 Finding、证据、风险等级和建议。
7. 高风险或证据不足进入人工审核；正式报告可导出并绑定任务、版本和审批。

## 业务规则

- 原文件事实字段不可被 LLM 修改。
- 每个问题至少引用文件、版本和页码。
- 高风险不能自动最终通过。
- 不同项目索引隔离；合同版本不可覆盖。
- 规则结果和 LLM 解释分开保存。

## 使用角色

项目工程师发起和查看；审核员/管理员审核高风险；普通用户只读被授权结果。

## 界面设计要求

- 文件清单、审查模板和风险阈值位于顶部配置区。
- 结果按商务/技术/风险/完整性分栏，并显示数量和严重级别。
- 每条问题展开可见原文页码、证据片段、规则和建议。
- 支持导出审查报告和查看任务时间线。

## API 与数据

- 问答意图：`bid_query`；任务工作流：`workflow=bid_review`。
- 统一入口：`POST /api/v2/chat/sessions/{id}/messages` 或 `POST /api/v2/workflows`。
- 使用 Artifact、ReviewRun、ReviewFinding、KnowledgeDocument/RetrievalRun。

## 异常与验收

- 解析失败、索引失败、文档版本冲突和无证据结论明确标记。
- 报告可从 Finding 回溯原文；高风险必须有审批记录。
