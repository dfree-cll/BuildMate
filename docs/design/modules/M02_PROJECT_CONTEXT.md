# M02 组织、项目与上下文设计

## 功能描述

管理组织、项目成员、楼层、坐标系、原点、比例和 Revit 工作模型策略，为所有业务任务提供统一的项目边界。

## 功能实现流程

1. 管理员创建租户和项目。
2. 项目管理员添加成员并授予项目角色。
3. 工程师配置单位、坐标原点、楼层编码、标高和 Revit Level 映射。
4. 前端选择项目，保存最近项目上下文。
5. 创建任务、Artifact、RAG 检索时自动注入项目 ID。
6. 项目归档后停止新任务，历史数据保持只读。

## 业务规则

- 项目编码在租户内唯一。
- 楼层编码在项目内唯一；Revit Level 必须显式映射，禁止猜测 `Main Level`。
- 坐标原点、单位和比例变更必须创建新版本并记录原因。
- 项目成员只能访问已授权项目。
- 项目归档不可启动新 Workflow，但允许查看和导出历史结果。

## 使用角色

- `admin`：创建项目、成员和全局策略。
- `project`：维护项目工程配置和发起任务。
- `reviewer`：读取被授权项目和处理审批。
- `user`：读取被授权项目上下文。

## 界面设计要求

- 项目切换器显示项目编号、名称和当前楼层。
- 项目设置分为“基本信息、楼层标高、坐标与单位、Revit 配置、成员”。
- 楼层映射表显示项目楼层编码与 Revit Level 名称，不允许空值提交。
- 危险配置变更显示影响范围和版本号。

## API 与数据

- `GET/POST /api/v2/projects`、`GET /projects/{id}`、`POST /projects/{id}/levels`。
- 表：`projects`、`project_memberships`、`project_levels`。
- 坐标和 Revit 策略存 JSONB/JSON，但查询字段（code、status、elevation）保持独立列。

## 异常与验收

- 项目不存在、无权限、楼层重复、Level 映射缺失、单位非法均明确返回。
- 任务详情可以显示创建时的项目配置快照，避免项目后续修改影响历史任务解释。
