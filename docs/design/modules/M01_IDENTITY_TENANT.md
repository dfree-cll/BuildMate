# M01 身份认证与租户设计

## 功能描述

提供登录、令牌、当前用户、租户成员和角色上下文。系统必须在任何业务动作前确认操作者身份、所属租户和角色。

## 功能实现流程

1. 用户提交用户名和密码。
2. API 校验账号状态、密码哈希和登录限制。
3. 签发短期 access token 和可轮换 refresh token。
4. 前端读取 `/api/v2/me`，加载可用租户、角色和项目。
5. 用户选择租户/项目后，后端为每个请求构造 `RequestContext`。
6. 退出或刷新令牌时使旧 refresh token 失效并记录审计事件。

## 业务规则

- 密码只保存 Argon2/bcrypt 哈希，禁止明文和日志记录。
- Token 不包含可变权限事实；权限以数据库成员关系为准。
- 用户必须属于租户才能访问租户资源。
- 角色为 `admin/reviewer/project/user`；Bridge 使用独立服务身份。
- 租户停用后拒绝全部业务请求，保留只读审计策略由管理员配置。
- 缺少 `tenant_id` 的请求不得进入 Repository。

## 使用角色

- 管理员：管理成员、角色和租户状态。
- 审核员、项目工程师、普通用户：登录并使用被授权项目。
- Bridge：使用受限服务令牌执行已批准任务。

## 界面设计要求

- 登录页提供用户名、密码、错误原因和重试提示。
- 登录后顶部固定显示租户、项目和角色。
- 无租户/项目上下文时显示阻断式提示，不静默选择默认值。
- 无权页面隐藏导航，同时直接访问显示统一无权限页。
- 退出和切换租户使用确认，切换后清空旧项目缓存。

## API 与数据

- `POST /api/v2/auth/login`、`POST /auth/refresh`、`POST /auth/logout`、`GET /me`。
- 表：`users`、`tenants`、`tenant_memberships`。
- 上下文：`tenant_id/project_id/user_id/role/trace_id/correlation_id`。

## 异常与验收

- 密码错误、账号禁用、令牌过期、租户不存在均返回可读错误和 Trace ID。
- 跨租户读取必须拒绝。
- 页面刷新后登录态可恢复；注销后旧 Token 不能继续调用。
