# M16 审核端设计

## 功能描述

将审核员角色从普通业务用户中独立出来，集中处理 BIM WallModel、图纸审查、合同审核、采购审批和知识待补。问答入口创建的正式审核任务统一汇入本端，不以聊天消息代替审批。

## 功能实现流程

1. 查询被授权项目的 `waiting_human` 任务。
2. 按风险、等待时间和工作流筛选。
3. 查看可读摘要、证据、图纸定位、构件属性、Dry-run、合同条款或采购事实。
4. 批准、驳回或要求补件，输入意见。
5. 系统记录审批并恢复/取消任务。

## 业务规则

- 审核员只能审批当前 `next_action` 匹配的阶段。
- Revit 写入必须在 WallModel 审批后再次审批。
- 版本不一致时必须重新查看，禁止覆盖新版本决定。
- 知识补全生成新文档版本，不覆盖历史版本。

## 使用角色

`reviewer` 和 `admin`；项目工程师默认只能提交和查看。

## 界面设计要求

- 审核首页展示待办数量、风险分布和等待时间。
- 详情页按“结论→证据→差异→动作”布局。
- BIM 显示墙柱/轴网/连接/碰撞和独立叠图指标。
- 驳回/补件必须填写原因；批准按钮显示具体阶段。

## API 与数据

- `/api/v2/tasks/{id}`、`/tasks/{id}/resume`、`/reviews/{id}/decision`。
- `approvals`、`review_findings`、`task_events`、`knowledge_feedback`。

## 异常与验收

- 无权项目、任务已终态、版本冲突和门禁失败不可审批。
- 审批后页面显示下一阶段和事件记录，不只弹出成功提示。
