# M19 测试、评估与发布治理设计

## 功能描述

建立从单元测试到前端真实端到端、RAG 评估、BIM 独立叠图、CI、迁移演练和版本回滚的统一质量门禁。

## 功能实现流程

1. 为领域、API、Repository、Agent、几何和 UI 建立测试夹具。
2. 运行单元、合同、集成、端到端和安全测试。
3. RAG 使用黄金问题集计算 Recall@K、MRR、nDCG、引用覆盖率和有据率。
4. BIM 使用固定/生成式 PDF/DWG 验证单位、坐标、去重、拓扑、异形柱、碰撞和 Revit 回读。
5. 使用独立源图和实际 Revit 视图计算 IoU、覆盖率、精确率和相似度。
6. CI 执行后端回归、前端 lint/typecheck/build、Compose 校验。
7. 发布前记录版本、测试数量、已知限制、回滚点和 CURRENT_STATUS。

## 业务规则

- 测试不得依赖未提交运行时 BIM 文件或用户本机临时路径。
- 不得修改测试来掩盖实现缺陷。
- 独立叠图不能使用同一 WallModel 反绘源图。
- 任一核心门禁失败不能发布为交付成功。
- 数据库迁移、权限和回滚必须演练。

## 使用角色

研发、测试、平台和产品；管理员查看发布状态和失败报告。

## 界面设计要求

- 管理台显示最近构建、测试数量、失败用例、覆盖指标和发布版本。
- 失败项显示实际日志摘要、Trace、是否可重试和回滚建议。
- 不把“跳过”显示为“通过”。

## API 与数据

- CI/发布脚本、测试报告、评估报告和版本清单。
- 关联 `workflow_runs`、`audit_events`、Artifact 和交付报告。

## 异常与验收

- 后端全量测试 0 失败，前端 build 通过，Compose 健康检查通过。
- 完成一次前端上传→审批→Revit→独立叠图→下载的真实验收。
- 未运行或跳过的检查必须明确记录原因。
