# Agent 记忆：当前实现与使用边界

更新：2026-09-05。本文描述已接入的代码，不代表模型训练或识别精度提升。

## 用户如何使用

问答、投标、采购、谈判和 BIM 页面均提供历史会话选择、恢复记录、新建会话、查看记忆与保存偏好。浏览器仅保存会话 ID；刷新后从数据库恢复记录。切换账号或项目使用不同的会话空间。

- QA：同一会话继续提问，历史窗口、较早对话摘要和用户偏好参与回答；简短追问用上一条用户问题补充检索上下文。
- 投标：同一会话再次提交文件是一次独立评审，新版本可参考前一版本的结论；每次评审保留不同 `review_id` 和执行检查点。不同项目/投标事项应新建会话。
- 采购：同一会话可包含多个订单，已经完成的订单及审批结果参与后续软审查。价格仍实时查询，旧批准不批准新订单；待审批订单仍从采购列表处理。
- 谈判：恢复原会话时延续标的、对话、阶段、报价与轮数；“开始新谈判”创建新会话，不覆盖原谈判。
- BIM：点击“记住当前建模设置”保存目标 RVT、楼层代号、标高范围、材料名称和 PDF 比例；点击“填入已记住的设置”后，必须核对再提交。成功任务及 Artifact 关联从持久化任务记录恢复；选择续建仍使用原有 `continue_from_task_id` 校验。
- 意图路由：用当前会话历史辅助理解“它/继续”等指代，并保存路由记录；不因为历史意图直接执行审批或建模。
- 聊天接口：先验证会话归属，再读取历史参与检索与生成；所有引用仍由本次真实召回结果校验。

新建会话不是删除历史。当前没有全量遗忘/保留期清理接口，也不会跨会话自动检索全部个人记录。

## 实现结构

`domain/agent_memory.py` 校验可记住的设置；`adapters/agent_memory_repository.py` 负责持久化和隔离；`application/agent_memory.py` 提供公共加载/保存节点与提示词上下文；`api/v2/memory.py` 提供前端接口。前端复用 `AgentMemoryPanel.vue` 和 Pinia `agentMemory` Store。

1. 输入携带可信用户、租户、项目、会话和本轮 ID。
2. 仅查询精确匹配的 `tenant_id + project_id + user_id + agent + session_id`。
3. 加载偏好、较早摘要、最近 10 轮，作为不可信历史上下文提供给 LLM。
4. 本次操作继续使用本次图纸、知识证据、价格和规则；历史结果不成为事实源。
5. 完成后保存本轮输入、回答、订单/评审/制品关联；重复 turn ID 不重复追加。
6. 对话检查点保留最近 20 条消息，长记录在业务数据库保存。

摘要是确定性的历史摘录（较早最近 20 轮），不是大模型推断的事实；上下文限制在 14,000 字符以内，避免额外摘要模型调用和无限增长。前端单次显示最近 100 轮，列表最多 50 个会话。历史全文不是无限窗口，也不是语义向量记忆。

## 数据与升级

- `agent_memory_sessions`：隔离标识、标题、滚动摘要、用户确认的偏好/设置、时间与版本。
- `agent_memory_turns`：顺序号、输入、回答、结构化结果关联、时间。按会话加锁分配顺序号，稳定本轮 ID 去重。
- LangGraph 检查点：用于恢复执行状态，和用户可阅读记忆分工不同。公共调用使用包含租户、项目、Agent 的哈希线程键；采购订单键按租户/所有者/订单隔离。
- PostgreSQL 新表增加租户和创建者 RLS；Repository 在 SQLite/PG 下都强制完整 Scope。缺失项目表示个人会话，不表示所有项目。
- 新迁移：`0011_agent_memory`，由既有启动迁移机制执行。不删除旧 `qa_sessions` 或旧检查点。
- 老 QA/谈判线程缺少可靠项目/Agent 归属，不自动批量混入新会话。老采购待审单在数据库确认所有者后，仅在旧检查点的租户、用户和订单一致时恢复。
- PG 检查点初始化失败明确停止启动，不降级到另一份 SQLite 记忆。

## API

所有接口均需登录，项目会话带 `project_id`。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v2/memory/{agent}/sessions` | 当前账号和项目的会话列表 |
| `GET /api/v2/memory/{agent}/sessions/{session_id}` | 摘要、偏好与最近历史 |
| `PUT /api/v2/memory/{agent}/sessions/{session_id}/preferences` | 保存显式用户偏好/安全 BIM 设置 |

`agent` 支持 `qa / bid_review / procurement / negotiation / drawing2bim / router / chat`。聊天接口 原始消息仍以 `chat_sessions_v2/chat_messages_v2` 为事实源，不额外复制到通用记忆表。

## BIM 明确不做的事

聊天偏好不能写入几何、族尺寸、规则阈值、脚本或批准标记。不会自动将某张图纸的人工几何修正应用于另一张图纸，也不会把“记住了”说成已训练识别模型。要复用已有 RVT 必须选择成功任务，并继续经过静态校验、Dry-run、本次人工批准、Bridge 和独立原图叠图审计。

## 验证范围

记忆链路覆盖跨连接恢复、租户/项目/用户/Agent/会话隔离、并发追加和幂等、摘要参与提示、BIM 设置拒绝非法值、成功模型记录恢复、谈判检查点重开、HTTP 问答/谈判/投标多版本/采购审批记忆、聊天接口授权与历史检索。

本次不操作真实 Revit、不重新生成模型，也不把 Mock LLM 的结果当作线上回答质量评估。生产 PostgreSQL 实例上的迁移与 RLS 集成验收需要部署环境验证。
